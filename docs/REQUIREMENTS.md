# 「需恋」AI 陪伴聊天 App — 需求基线（用户原始需求）

> 本文件为团队共享的需求基线（PRD 输入源）。所有架构、实现、测试均以此为准。

## 一、产品定位

「需恋」是一款 AI 陪伴型聊天软件。核心体验：用户可以创建一个拥有稳定人格、情绪、记忆和主动性的 AI 陪伴角色，并与它进行长期、自然的互动。

AI 需要表现出：相对稳定的人格 / 当前情绪 / 说话风格 / 长期记忆 / 对用户情绪的理解能力 / 根据上下文调整聊天方式的能力 / 主动发起聊天的能力 / 随着长期互动产生自然关系变化的能力。

**底线：AI 是 AI 角色，不应欺骗用户声称自己是真实人类，也不应制造用户必须依赖 AI 的感觉。**

## 二、核心功能（14 项，需形成闭环）

1. AI 被动聊天
2. AI 主动聊天
3. AI Persona 人格系统
4. AI 情绪系统
5. 用户情绪分析
6. 安慰策略
7. 短期记忆
8. 长期记忆
9. AI 与用户关系成长
10. 主动聊天决策系统
11. 手机推送通知
12. 内容安全系统
13. 隐私和数据管理
14. 手机端 UI
15. AI 角色创建和编辑

## 三、AI Persona 人格系统

每个 AI 角色至少包含：名称、头像、性格、说话风格、兴趣、喜欢的话题、不喜欢的话题、与用户的关系类型、当前情绪、主动聊天倾向、主动聊天时间、主动聊天频率、AI 的称呼方式、AI 回复长度倾向。

**每次生成回复时，都必须让 Persona 真正参与 AI 回复。**

## 四、人格稳定性

每次生成回复至少综合：Persona + AI 当前情绪 + 用户当前情绪 + 当前对话上下文 + 短期记忆 + 长期记忆 + 双方关系阶段 + 安全规则。

保证：性格长期稳定、说话风格稳定、称呼稳定、兴趣设定稳定、关系连续。AI 可因情绪变化改变语气，但不能因一次情绪变化完全改变人格。

## 五、AI 情绪系统

至少支持：开心 / 平静 / 兴奋 / 害羞 / 关心 / 失落 / 难过 / 生气 / 担心 / 惊讶。

每个情绪至少包含：`emotion`、`intensity`、`updatedAt`、`emotionReason`。

情绪随对话动态变化（平静→开心；平静→关心；长时间未回复→轻微关心/想念）。

**禁止**：通过"你不回复我我会难过""你离开我我很痛苦"等方式制造用户负罪感或强迫用户回来。

## 六、用户情绪分析

独立模块，判断：情绪倾向 / 情绪类型 / 情绪强度 / 情绪变化 / 当前聊天意图 / 是否可能需要安慰 / 更适合普通聊天、倾听、安慰、鼓励还是转移话题。

需能检测"用户情绪发生明显变化"（连续表达压力/失落/难过/焦虑/生气）。

## 七、安慰策略系统

独立"回复策略选择器"，至少包含：
- `normal_chat`：普通聊天
- `listening`：倾听
- `comfort`：安慰
- `encouragement`：鼓励
- `companionship`：陪伴
- `topic_change`：转换话题

**不要机械化安慰**。核心原则：先理解用户当前情绪，再决定怎么回应。

## 八、记忆系统

### 短期记忆
保存最近聊天上下文，保证当前对话连续、理解上一句话、维持当前话题。不要无限发送全部历史。

### 长期记忆
提取：用户喜欢/不喜欢的东西、兴趣、主动介绍的信息、长期习惯、重要事件、喜欢的称呼、希望的交流方式。

需要支持：查看 / 修改 / 删除 / 全部清空 / 关闭长期记忆。不自动保存不必要敏感信息。

## 九、关系成长系统

阶段：初识 → 熟悉 → 亲近 → 默契。

参考：聊天频率、互动持续时间、用户主动分享信息、AI 长期记忆、用户互动、用户选择的关系类型。

影响：AI 熟悉程度、表达方式、聊天内容、了解程度、主动聊天倾向。

**禁止**：不登录就下降的惩罚机制、诱导消费。

## 十、AI 主动聊天决策系统（核心特色）

禁止"每隔 3 小时固定发一条"。

决策依据：距上次聊天时间 / 最近聊天内容 / 用户最近情绪 / AI 当前情绪 / AI Persona / 双方关系阶段 / 用户主动聊天设置 / 今日已主动聊天次数 / 当前时间 / 用户免打扰设置 / 用户最近是否刚打开 App。

输出三种判定：不联系 / 延迟联系 / 主动发送消息。

## 十一、主动消息生成

输入：Persona + AI 当前情绪 + 最近聊天 + 长期记忆 + 关系阶段 + 用户最近状态 + 当前时间。

行为示例：想起用户昨天说的事、询问之前提到的事的进展、分享符合人格的话、合适时机问候、根据最近聊天自然开启话题。

**禁止**：负罪感文案（"你为什么不理我""你是不是不要我了""你再不回来我会很难过"）。

## 十二、主动聊天后台机制（服务端）

```
Scheduler / Background Job
↓ 检查符合条件的用户
↓ 读取用户设置 → 检查免打扰 → 检查频率
↓ 读取最近聊天 / 用户情绪 / AI 状态 / 关系阶段
↓ AI 主动性决策 → 决定是否发送
↓ 生成主动消息 → 保存 Message → Push Notification
```

需考虑：每日上限、免打扰时间、主动聊天开关、推送开关、防重复、防短时间连续发送、刚打开 App 后避免重复推送、AI API 失败、推送失败、Job 重试、Job 幂等性。

## 十三、主动聊天设置

- AI 主动聊天：开启/关闭
- 每日主动消息上限
- 主动聊天时间段
- 免打扰时间
- 是否允许推送
- 是否允许 AI 根据最近聊天主动开启话题

默认设置不要过度打扰。

## 十四、AI 状态感

轻量级状态：当前情绪、活跃程度、最近互动时间、最近主动聊天时间、当前关系阶段。

状态影响聊天（晚上安静、白天轻松）。**AI 不得声称自己在现实世界真的做了某些活动。**

## 十五、手机聊天界面

真正的手机 App 体验，不是桌面 Web 缩小版。

需要：AI 头像 / 用户头像 / 消息气泡 / 底部输入框 / 发送按钮 / AI 正在输入状态 / 流式输出 / 消息时间 / 自动滚动 / 历史聊天 / 长按消息 / 删除消息 / 重新生成 AI 回复 / 网络异常提示 / AI 回复失败重试 / 空状态页面。

视觉风格：简洁、温柔、现代、有陪伴感。App 名称：**需恋**。需自行设计简单 Logo 与视觉风格，不得复制其他产品 Logo/图片/品牌/受版权保护 UI。

## 十六、首页

至少包括：当前 AI 角色、AI 当前情绪、最近聊天、AI 最近状态、快速进入聊天、AI 主动消息、角色管理。可选："今天的 AI 状态"。不要过度复杂。

## 十七、AI 角色创建页面

- 基础信息：AI 名称、AI 头像
- 人格：性格、说话风格、兴趣、喜欢的话题、不喜欢的话题
- 情绪：初始情绪、情绪敏感程度
- 互动：主动聊天程度、回复长度、用户称呼
- 关系：关系类型、初始关系阶段

提供预设模板，也支持自定义。

## 十八、禁止购买第三方聊天模板

自行实现聊天 UI 与 AI 陪伴逻辑。可借鉴公开产品的信息架构与交互思路，但不得复制代码、Logo、图片、品牌设计或受版权保护内容。

## 十九、内容安全

AI 不主动引导、不鼓励、不提供帮助：色情/淫秽内容、毒品、赌博、其他明显违法或危险行为。

用户主动讨论时：适当拒绝并自然转移到安全话题。不得生成露骨色情内容，不得诱导危险行为。

## 二十、心理安全

用户情绪分析不得描述成专业心理诊断。AI 只能：理解语言情绪、判断聊天策略、提供一般性倾听与陪伴。

**不得说**："我诊断出你患有某种心理疾病。"

检测到严重心理危机信号时：不声称可代替专业帮助，采用安全温和回应，鼓励联系现实中可信任的成年人、家人、老师或专业帮助。

## 二十一、隐私和数据安全

用户数据隔离 / 会话数据安全保存 / API Key 不暴露前端 / AI API 调用放后端 / 敏感配置用环境变量 / 删除聊天记录 / 删除 AI 角色 / 清除长期记忆 / 关闭长期记忆 / 清除全部用户数据。

用户拥有对自己聊天记录和 AI 记忆的控制权。

## 二十二、推荐数据模型

- **User**：id, settings, notificationSettings, privacySettings, createdAt, updatedAt
- **AICharacter**：id, userId, name, avatar, personality, emotion, speakingStyle, interests, relationshipType, proactiveChatSettings, createdAt, updatedAt
- **Conversation**：id, userId, characterId, createdAt, updatedAt
- **Message**：id, conversationId, role, content, emotion, strategy, isProactive, createdAt
- **Memory**：id, userId, characterId, content, importance, category, createdAt, updatedAt
- **EmotionState**：id, userId, characterId, currentEmotion, intensity, emotionReason, updatedAt
- **UserEmotionAnalysis**：id, conversationId, messageId, emotion, confidence, intensity, needsComfort, createdAt
- **RelationshipState**：id, userId, characterId, stage, interactionLevel, updatedAt
- **ProactiveMessageTask**：id, userId, characterId, scheduledAt, status, reason, createdAt

## 二十三、技术要求

- 优先使用 CodeBuddy SDK（`@tencent-ai/agent-sdk`）完成 AI 对话能力
- 技术栈以 `codebuddy-chat-web` Skill 模板为基础：TypeScript + React 18 + Express 4 + SQLite(better-sqlite3) + Vite 5 + TDesign React + Tailwind CSS + SSE 流式
- 目标 Android / iOS，第一阶段做移动端 Web / PWA 原型
- 以下功能设计为**独立服务**：Chat / Persona / Emotion / Memory / Relationship / Proactive / Safety / Notification
- 不要把所有核心业务逻辑写死在 UI 中

## 二十四、AI 对话处理流程

```
用户发送消息
↓ 内容安全检查
↓ 读取 AI Persona
↓ 读取 AI 当前情绪
↓ 分析用户情绪
↓ 分析用户聊天意图
↓ 读取短期记忆
↓ 读取相关长期记忆
↓ 读取关系阶段
↓ 选择回复策略
↓ 构建 AI Context
↓ 调用 CodeBuddy SDK
↓ 流式生成回复
↓ 显示给用户
↓ 更新 AI 情绪
↓ 更新用户情绪状态
↓ 提取重要长期记忆
↓ 更新关系状态
↓ 保存消息
```

## 二十五、AI 主动聊天处理流程

```
用户离开 App
↓ 后台 Scheduler
↓ 判断是否达到主动聊天条件
↓ 读取用户设置 → 免打扰 → 次数
↓ 读取最近聊天 / 用户情绪 / AI 情绪 / Persona / 长期记忆 / 关系阶段
↓ 主动性决策
↓ 不适合联系 → 结束
↓ 生成主动消息 → 安全检查 → 保存消息 → Push Notification
↓ 用户点击通知 → 进入聊天页 → 继续正常对话
```

## 二十六、开发阶段

- Phase 1 初始化：SDK、前后端结构、数据库、手机端 UI、基础聊天、流式回复
- Phase 2 Persona：创建/编辑角色、人格、说话风格、兴趣、称呼
- Phase 3 AI 情绪：当前情绪、强度、变化、影响回复
- Phase 4 用户情绪：分析、变化、回复策略、安慰/倾听/鼓励
- Phase 5 记忆：短期、长期、提取、查看、删除
- Phase 6 关系成长：阶段、互动状态、与 Persona 联动
- Phase 7 主动聊天：决策、Scheduler、后台任务、推送、频率限制、免打扰
- Phase 8 安全隐私：内容安全、数据删除、隐私设置、API Key 安全、用户控制
- Phase 9 全面测试

## 二十七、开发原则

1. 不过度复杂化第一版，先保证核心闭环：**人格 → 情绪 → 用户情绪 → 记忆 → 回复 → 关系 → 主动聊天**
2. 不做假 UI（心情显示必须真的影响回复；记忆必须真的保存；主动聊天必须真有后台任务）
3. 主动聊天不能是固定定时器，必须存在真正的主动性判断
4. 不让 AI 制造情感压力（禁止内疚/威胁/情绪勒索/强制关系/诱导持续使用）
5. 用户永远拥有控制权（关闭主动聊天/通知/长期记忆、删除记忆/聊天/角色/数据）

## 二十八、最终产品体验

> 「需恋」不是一个普通 AI 聊天机器人，而是一个拥有稳定人格、当前情绪、长期记忆、关系状态，并能够理解用户情绪、适时主动聊天的 AI 陪伴角色。

闭环：**聊天 → 情绪理解 → 记忆 → 关系成长 → 主动陪伴 → 再次聊天**
